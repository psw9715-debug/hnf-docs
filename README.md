# 혀니네홈패션 거래문서 자동화 앱

아이폰(또는 PC) 브라우저만으로 — 업체 선택 → 품목 입력(직전 거래이력 자동 불러오기) → 거래명세표 / 납품확인서 / 견적서 생성(발송과 분리) → Gmail 발송 → 이 저장소에 PDF 백업 → 발송이력 조회/재발송까지 되는 단일 정적 웹앱입니다.

`psw9715-debug/fabric-calc`와 동일한 패턴(GitHub Pages + GitHub Gist)으로 만들어졌습니다.

## 구성

- `index.html`, `app.js` — 앱 본체 (빌드 과정 없는 순수 HTML/CSS/JS)
- `vendor/jspdf.umd.min.js`, `vendor/html2canvas.min.js` — PDF 생성 라이브러리 (CDN 대신 저장소에 직접 포함 — 오프라인/CDN 장애에도 동작)
- `assets/stamp.png` — 도장 이미지(원본 엑셀에서 추출), `app.js`에 base64로도 내장되어 있어 실제로는 이 파일이 로드되지 않아도 됩니다.

## 처음 설정할 때 해야 하는 일

### 1. GitHub Pages 켜기
저장소 Settings → Pages → Branch를 이 브랜치(또는 병합 후 main)로 지정하면 `https://psw9715-debug.github.io/hnf-docs/` 로 접속할 수 있습니다.

### 2. GitHub 토큰 연결 (여러 기기에서 같은 주소록/이력 보기)
앱의 ⚙️ 설정 화면에서 "토큰 발급 방법 보기"를 눌러 안내를 따라 Personal Access Token(gist 권한만)을 발급하고 붙여넣습니다. 토큰은 이 기기의 localStorage에만 저장됩니다.

### 3. Google Cloud OAuth 클라이언트 발급 (계정 소유자가 직접 해야 하는 유일한 단계)
`suhyunfabric@gmail.com`으로 로그인한 뒤 설정 화면의 "발급 방법 보기" 버튼을 누르면 단계별 안내가 나옵니다. 요약:

1. console.cloud.google.com → 새 프로젝트 생성
2. Gmail API, Google Drive API 사용 설정
3. OAuth 동의화면(외부, 테스트 모드) 생성 → 테스트 사용자에 `suhyunfabric@gmail.com` 추가
4. OAuth 클라이언트 ID(웹 애플리케이션) 발급 → 승인된 자바스크립트 원본에 `https://psw9715-debug.github.io` 추가
5. 발급된 클라이언트 ID를 앱 설정 화면에 붙여넣기

**중요:** 이미 만들어져 있는 거래처 Drive 폴더(작업지시서 6장)에 파일을 쓸 수 있어야 하므로, `drive.file`이 아니라 **`https://www.googleapis.com/auth/drive` (전체 Drive 접근) 범위**를 요청합니다. 테스트 모드 앱이라 "확인되지 않은 앱" 경고가 뜰 수 있는데, 본인 계정만 테스트 사용자로 등록해서 쓰는 용도라 "고급 → 이동(안전하지 않음)"으로 진행해도 안전합니다.

최초 1회만 "구글 로그인" 버튼으로 동의하면, 이후엔 PDF 생성 버튼을 누를 때(또는 앱을 열 때 백그라운드로) 조용히 토큰을 다시 받아옵니다 — 계정 선택 화면이 다시 뜨는 건 구글 세션 자체가 끊겼을 때뿐입니다. (다만 사파리의 개인정보 보호 정책(ITP) 때문에 조용한 갱신이 종종 막혀 계정 선택 화면이 다시 뜰 수 있습니다 — 앱이 어찌할 수 없는 브라우저 차원의 제약입니다.)

## 아직 사용자 확인이 필요한 것 (작업지시서 9장 기준)

- **(주)호산비전 / 로엘라이즈브레이브 / (주)인아트 담당자 이메일** — 3곳 다 이메일이 비어 있어서 지금 상태로는 발송이 안 됩니다. 앱의 📇 주소록에서 채워주세요. 로엘라이즈브레이브·인아트는 사업자번호/주소/대표자/담당자 정보도 비어 있습니다.
- **Google Cloud OAuth 클라이언트 ID 발급** — 계정 소유자만 할 수 있는 수동 단계 (위 안내 참고).
- **문서 여러 개 선택 시 이메일을 한 통에 합쳐 보낼지** — 이번 버전은 **한 통에 모두 첨부**하는 방식으로 구현했습니다. 개별 발송을 원하시면 알려주세요.
- **한글 폰트** — Noto Sans KR 임베딩 대신, 문서를 화면에 그대로 그린 뒤 캡처해서 PDF에 붙이는 방식(html2canvas + jsPDF)을 사용했습니다. 텍스트가 선택되지 않는 이미지형 PDF이지만, 폰트 라이선스/서브셋 문제 없이 원본 레이아웃을 그대로 재현할 수 있어서 이 방식을 택했습니다.
- **OAuth 토큰 만료(약 1시간) 시 동작** — 최초 로그인 이후엔 만료돼도 조용히(팝업 없이) 다시 받아오려고 시도하고, 그것도 실패할 때만 로그인 화면을 다시 띄웁니다.

## 주요 기능 메모

- 업체 카드를 탭하면 바로 그 업체의 **가장 최근 거래 품목이 자동으로 채워집니다** (1순위 요구사항).
- 문서 3종은 동시에 여러 개 선택할 수 있습니다.
- **생성(PDF 생성)과 발송이 분리**되어 있습니다. "PDF 생성"을 누르면 PDF를 만들면서 **그 자리에서 바로 GitHub 저장소 + Google Drive 양쪽에 백업**하고, "발송하기"는 그렇게 이미 백업된 파일을 그대로 첨부해서 이메일만 보냅니다. 생성 후 품목/문서종류/발송일자를 바꾸면 발송 버튼이 다시 비활성화되며 재생성을 안내합니다.
- **발송일자**를 직접 지정할 수 있습니다 (기본값 오늘). 작업은 며칠 전에 끝났는데 서류(납품확인서 등)를 나중에 보내는 경우처럼, 문서에 찍히는 날짜를 실제 발송 시점과 다르게 지정할 때 씁니다.
- PDF는 **① 이 저장소의 `pdf-archive/{거래처명}/` 아래(공개)** 와 **② 거래처별 Google Drive 폴더(비공개, 작업지시서 6장 폴더 ID가 기본으로 들어있음)** 두 곳에 백업됩니다. `hnf-docs`는 무료 GitHub Pages를 쓰기 위해 공개 저장소라, ①에 저장되는 PDF(거래처명·연락처·단가 포함)는 인터넷에 공개된다는 점을 인지한 상태로 이렇게 결정했습니다 — 실제로 열어보거나 공유할 땐 ②의 Drive 링크를 쓰는 게 안전합니다. 새 업체는 Drive 폴더가 없으면 첫 생성 시 상위 폴더 아래 자동 생성됩니다.
- **이메일 제목/본문은 자동으로 채워지고**, 발송 화면에서 "추가할 코멘트"를 선택적으로 입력하면 기본 인사말 뒤에 덧붙여 나갑니다.
- **발송이력 화면에서 "다시 보내기"**로, 거래처가 "못 받았다"고 할 때 PDF를 다시 만들지 않고 GitHub에 저장된 그 파일 그대로 재발송할 수 있습니다.
- 파일명 규칙: `YYYYMMDD_업체명_문서종류.pdf` (YYYYMMDD는 발송일자 기준)
